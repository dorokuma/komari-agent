# 2026-11-08 上游 1.5.11 同步 C 档门禁 consider 留痕（cgroup CPU 分母与 shutdown 退出码）

## 一句话结论

登记 `chore/sync-upstream-1.5.11` 分支 2026-11-08 C 档门禁第一轮 oracle 审查通过后尚未闭环的 2 条非阻断观察项：容器内 `cpu.max` 为 `max` 时 cgroup CPU 分母未计入 `cpuset.cpus.effective` 绑核限核场景（存量设计），以及 `shutdownCoordinator.shutdown` 并发退出码较大者胜出的竞态窗口（上游 1.5.11 有意设计）；并补录本轮返修审查指出的 5 条上游 1.5.11 原生未修改代码条目（terminal 重连竞态、文件复制硬链接自截断、跨挂载 rename、上传截断、MOTD 临时文件，均 out-of-scope / consider，运行时已由 `--disable-web-ssh` 关闭相关功能面）。

## 背景

在上游 `1.5.11` 同步合并（`chore/sync-upstream-1.5.11` 分支，`MERGE_HEAD` 未提交态）执行 C 档门禁第一轮 oracle 审查时，结论为通过，同时提出 2 条非阻断观察项。按门禁纪律新建本笔记逐条留痕。

## 决策（观察项逐条留痕）

### [pattern:cgroup-cpuset-unbounded-quota] O1：容器内 `cpu.max` 为 `max` 时回退分母取整机在线核数，未计入 `cpuset.cpus.effective` 绑核限核

- **出处**：`monitoring/unit/cpu.go:296`（`cgroupCPULimit` 在 `cpu.max` 解析不到有限配额时回退读取 `/sys/devices/system/cpu/online`）。
- **问题**：容器内 cgroup v2 `cpu.max` 为 `max`（无配额限制）时，回退分母取整机在线核数；若容器仅经 `cpuset.cpus.effective` 绑核限核而未设 `cpu.max` 配额，CPU 使用率分母仍按整机核数计算，未反映绑核后的实际可用核数（存量设计，当前受控 LXC 节点未命中或符合预期）。
- **建议**：后续若部署绑核限核节点且 CPU 使用率明显偏低，考虑读取 `cpuset.cpus.effective`（cgroup v2）作为 `cpu.max == max` 时的次级回退分母。
- **不阻断理由**：存量设计行为，当前受控 LXC 节点未命中该场景或结果符合预期；非本次 1.5.11 同步引入。
- **后续处置条件**：观察到绑核限核节点 CPU 使用率失真时再立项修复。

### [pattern:shutdown-exitcode-race-window] O2：`shutdownCoordinator.shutdown` 在 `stopNetstatic()` 期间并发较大退出码胜出

- **出处**：`cmd/shutdown.go:25-42`（上游 `1.5.11` 引入的 `shutdownCoordinator.shutdown`）。
- **问题**：`shutdown(0)` 与 `shutdown(42)` 在 `stopNetstatic()` 执行窗口内并发到达时，`once.Do` 内重新读取 `s.exitCode` 取较大值，退出码 `42` 胜出，存在短暂竞态窗口。
- **说明**：该行为属上游 `1.5.11` 有意设计的保重启语义——`42`（`ErrRestartRequired` 自更新重启）优先于 `0`（常规信号退出），保证自更新路径不被并发信号退出截断。
- **不阻断理由**：上游有意设计，语义正确（保重启优先），留痕备查。
- **后续处置条件**：同步上游 `shutdownCoordinator` 后续版本变更时复核该语义是否保持。

## 决策（本轮返修补录：上游 1.5.11 原生未修改代码条目）

以下 5 条为本轮 reviewer 与 oracle 指出的上游 `1.5.11` **原生未修改**代码问题（`git diff c7bafb79b1a73ed9e14e2c248ae4d4163e506036 -- terminal/terminal.go server/files.go cmd/warn_linux.go` 已核实为空，属上游既有代码，非本次同步引入，本次不修改）。相关功能面（WebSSH 与远程文件管理）由 `--disable-web-ssh` 统一控制；我方 **9 台主机全部启用 `--disable-web-ssh`**，运行时已关闭 WebSSH 与远程文件管理，下列条目在当前部署形态不可达或影响受控。

### [pattern:reconnect-timer-generation-race] U1：`terminal/terminal.go` 断线保留计时器与重连竞态

- **出处**：`terminal/terminal.go:105-112,200-229`（上游原生代码）。
- **分诊**：out-of-scope。
- **问题**：断线保留计时器回调等锁期间若发生重连，`Stop` 返回 `false` 后回调仍会删除会话并关闭新连接。
- **不修改理由**：上游原生缺陷，修改属本地偏离上游，增加后续同步冲突；我方运行时 `--disable-web-ssh` 已关闭 WebSSH 入口，代码路径不可达。

### [pattern:copy-hardlink-self-truncate] U2：`server/files.go` 复制到同源硬链接自截断

- **出处**：`server/files.go:342`（`copyRegularFile` 未做 `os.SameFile` 校验，上游原生代码）。
- **分诊**：out-of-scope。
- **问题**：复制目标与源为同一 inode 的硬链接时，`O_TRUNC` 打开目标会清空源文件内容。
- **不修改理由**：上游原生缺陷；远程文件管理随 `--disable-web-ssh` 关闭，当前部署不可达。

### [pattern:rename-cross-mount-exdev] U3：`server/files.go` 跨挂载点 `os.Rename` 无 EXDEV 回退

- **出处**：`server/files.go:236-239`（`replaceFile` 上游原生代码）。
- **分诊**：consider / out-of-scope。
- **问题**：临时文件与目标跨挂载点时 `os.Rename` 返回 EXDEV 而无拷贝回退，替换失败。
- **不修改理由**：上游原生缺陷；`--disable-web-ssh` 下远程文件管理不可达，临时文件与目标同目录时亦不跨挂载。

### [pattern:upload-oversize-truncate] U4：`server/files.go` 上传超界字节截断语义

- **出处**：`server/files.go:497-510`（`commitFileUpload` 上游原生代码）。
- **分诊**：consider / out-of-scope。
- **问题**：上传声明大小与实际接收字节不一致时按声明长度截断/落盘，语义依赖面板侧约束。
- **不修改理由**：上游原生语义；`--disable-web-ssh` 下文件上传不可达。

### [pattern:motd-sigkill-temp-leftover] U5：`cmd/warn_linux.go` `writeMOTD` 遭 SIGKILL 遗留临时文件

- **出处**：`cmd/warn_linux.go`（`writeMOTD` 上游原生代码）。
- **分诊**：consider / out-of-scope。
- **问题**：临时文件 rename 前若进程遭 SIGKILL，`/etc/motd` 目录遗留 `.*` 临时文件（SIGKILL 不可捕获，常规信号已有清理）。
- **不修改理由**：上游原生缺陷且属不可捕获信号路径，残留仅为空临时文件，影响极小。

## 被放弃的方案（必填）

- **方案 A**：本轮直接为 `cpu.max == max` 场景接入 `cpuset.cpus.effective` 次级回退分母。放弃原因：存量设计、当前部署形态未命中，扩改本次同步 diff 范围不符合最小化纪律，留痕观察更稳妥。
- **方案 B**：本轮修改 `shutdownCoordinator` 并发退出码择取逻辑（如固定先到先得）。放弃原因：属上游有意设计的保重启语义，本地偏离上游会增加后续同步冲突且行为更差。
